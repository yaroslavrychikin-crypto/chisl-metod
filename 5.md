# Максимально простой скрипт для сравнения «циклы vs NumPy»

Один файл, без импортов из других файлов, без `tracemalloc`, без `ast`. Только `time.perf_counter()` и `print`. Запускается как есть.

```python
# compare_simple.py
# Запуск: python compare_simple.py
# Что делает: гоняет одну и ту же задачу двумя способами (цикл и NumPy),
# замеряет время, печатает ускорение. Всё.

import time
import numpy as np


# ── Данные: один массив на миллион чисел ───────────────────
# seed фиксирован, чтобы каждый запуск был на одних и тех же данных.
rng = np.random.default_rng(42)
a = rng.normal(size=1_000_000)


# ── Способ 1: обычный цикл Python ──────────────────────────
def loop_sum(arr):
    total = 0.0
    for x in arr:
        total += x
    return total


# ── Способ 2: NumPy ────────────────────────────────────────
def numpy_sum(arr):
    return arr.sum()


# ── Замер: запускаем 3 раза, берём лучший (минимум) ────────
def measure(fn, arr, repeat=3):
    best = float("inf")
    result = None
    for _ in range(repeat):
        t0 = time.perf_counter()
        result = fn(arr)
        t1 = time.perf_counter()
        best = min(best, t1 - t0)
    return result, best


# ── Сравнение ──────────────────────────────────────────────
r_loop,  t_loop  = measure(loop_sum,  a)
r_numpy, t_numpy = measure(numpy_sum, a)

print(f"цикл:   {t_loop*1000:10.2f} мс   результат = {r_loop:.6f}")
print(f"NumPy:  {t_numpy*1000:10.2f} мс   результат = {r_numpy:.6f}")
print(f"ускорение: {t_loop / t_numpy:.1f}×")
print(f"результаты совпадают: {np.isclose(r_loop, r_numpy)}")
```

**Что вы увидите (примерно):**

```
цикл:      45.30 мс   результат = 1234.567890
NumPy:      1.20 мс   результат = 1234.567890
ускорение: 37.8×
результаты совпадают: True
```

## Как этим пользоваться в 15 задачах

Меняете только две функции (`loop_sum` и `numpy_sum`) и строку с данными. Всё остальное — копипаста.

**Пример для задачи «сумма по строкам матрицы»:**

```python
import time
import numpy as np

rng = np.random.default_rng(42)
m = rng.normal(size=(100_000, 10))


def loop_sum_rows(mat):
    result = [0.0] * mat.shape[0]
    for i in range(mat.shape[0]):
        s = 0.0
        for j in range(mat.shape[1]):
            s += mat[i, j]
        result[i] = s
    return result


def numpy_sum_rows(mat):
    return mat.sum(axis=1)


def measure(fn, x, repeat=3):
    best = float("inf")
    result = None
    for _ in range(repeat):
        t0 = time.perf_counter()
        result = fn(x)
        t1 = time.perf_counter()
        best = min(best, t1 - t0)
    return result, best


r_loop,  t_loop  = measure(loop_sum_rows,  m)
r_numpy, t_numpy = measure(numpy_sum_rows, m)

print(f"цикл:   {t_loop*1000:10.2f} мс")
print(f"NumPy:  {t_numpy*1000:10.2f} мс")
print(f"ускорение: {t_loop / t_numpy:.1f}×")
print(f"результаты совпадают: {np.allclose(r_loop, r_numpy)}")
```

---

## Три правила, чтобы замер был честным

1. **`repeat=3` и берём минимум.** Первый прогон может быть медленным из-за прогрева кеша/импорта. Минимум по нескольким прогонам стабильнее среднего.
2. **Одни и те же данные для обоих способов.** Один `rng = default_rng(42)`, массив создаётся один раз до замеров.
3. **Сравнивайте результаты, а не только время.** Строка `np.isclose` / `np.allclose` — это ваша проверка, что «быстрее» не значит «неправильно».

## Блок 1. Основные операции (задачи 1–4)

**Задача 1. Сумма массива.**
Сравните:
- цикл `for x in a: s += x`;
- `a.sum()`.

Запустите `compare` на `n = 10^5, 10^6, 10^7`. Постройте таблицу «n → ускорение». Оцените, как ускорение зависит от `n` и почему. В выводе ответьте: при каком `n` разница становится заметной (>10×)?

**Задача 2. Среднее и стандартное отклонение.**
Реализуйте среднее и std:
- «в лоб»: цикл с суммой и суммой квадратов, потом формула;
- NumPy: `a.mean()`, `a.std()`.

Сравните на `n = 10^6`. Проверьте, совпадают ли результаты до `1e-12`. Объясните: почему NumPy считает std **устойчивее** (подсказка: NumPy использует двухпроходный алгоритм или компенсированное суммирование).

**Задача 3. Поэлементное преобразование: \(y = \sin(x) + x^2\).**
Реализуйте:
- цикл с `math.sin(x) + x*x`;
- NumPy: `np.sin(a) + a**2`.

Сравните на `n = 10^6`. Обратите внимание на **память**: сколько выделяет цикл (список Python) и сколько NumPy (один массив). Объясните, почему NumPy-версия короче, но при этом использует временные массивы (сколько их в `np.sin(a) + a**2`?).

**Задача 4. Условная замена (clipping).**
Замените все значения `< 0` на 0, все `> 1` на 1:
- «в лоб»: цикл с `if/elif`;
- NumPy: `np.clip(a, 0, 1)`.

Сравните на `n = 10^6`. Посчитайте, сколько элементов было изменено (`np.sum((a < 0) | (a > 1))`) — это полезная побочная статистика. Оцените, во сколько раз NumPy короче: у цикла будет 2 `if` и 1 `for`, у NumPy — 0 циклов и 0 `if`.

**Задача 5. Сумма по строкам матрицы.**

Сравните. Проверьте, что средние после нормировки ≈ 0. Обратите внимание: NumPy-версия — **одна строка**, цикл — минимум 6 строк. Оцените разницу в SLOC и в `indexes`.

**Задача 7. Поиск максимума и его индекса.**
Дан `a` длины `10^6`:
- цикл: пройти, запомнить `max_val` и `max_idx`;

Сравните. Затем проверьте на данных с NaN: цикл «сломается» (NaN сравнения дают False), а `np.nanmax` — работает. Сделайте вывод: почему NumPy-функции с префиксом `nan` — это не «фича ради фичи», а защита от реальных данных.

## Блок 3. Фильтрация и маски (задачи 8–10)

**Задача 8. Фильтрация по порогу.**
Дан `a` длины `10^6`:
- цикл: `[x for x in a if x > 0]` (список Python);
- NumPy: `a[a > 0]`.

Сравните время и память. Обратите внимание: результат цикла — **список** Python, результат NumPy — **массив**. Посчитайте, во сколько раз NumPy-массив компактнее по памяти (список float Python ≈ 24 байта на элемент + указатели, ndarray float64 = 8 байт на элемент). Сделайте вывод.

**Задача 9. Замена по маске (in-place).**
Дан `a` длины `10^6`. Замените все отрицательные на их модуль:
- цикл: `for i in range(n): if a[i] < 0: a[i] = -a[i]`;
- NumPy: `a[a < 0] *= -1` (или `np.abs(a, out=a)`).

Сравните. Проверьте, что оба варианта не создают новый массив (in-place). Объясните: почему in-place в NumPy важен для больших данных (не хватает памяти на копию).

**Задача 10. Комбинированная маска.**
Дан `a` длины `10^6`. Выберите элементы, для которых `(a > -1) & (a < 1)`:
- цикл: `if -1 < x < 1`;
- NumPy: `a[(a > -1) & (a < 1)]`.

Сравните. Обратите внимание: в Python условие `-1 < x < 1` — читаемое, а в NumPy нужно `(a > -1) & (a < 1)` — скобки обязательны, иначе `ValueError`/неверный результат. Объясните: почему в NumPy нельзя написать `a > -1 & a < 1` (подсказка: приоритет `&` и сравнений).

## Блок 4. Реальные кейсы (задачи 11–15)

**Задача 11. Расстояния между точками.**
Даны `X` формы `(n, 3)` и `Y` формы `(m, 3)`, `n = 1000`, `m = 1000`. Посчитайте матрицу евклидовых расстояний `D[i, j] = ||X[i] - Y[j]||`:
- цикл: двойной `for i in range(n): for j in range(m)`;
- NumPy: broadcasting `np.sqrt(((X[:, None, :] - Y[None, :, :])**2).sum(axis=2))`.

Сравните время. Оцените память: `X[:, None, :] - Y[None, :, :]` создаёт временный массив `(1000, 1000, 3)` — сколько это МБ? Предложите, как уменьшить память (подсказка: `scipy.spatial.distance.cdist` или формула через `X @ Y.T`). Сделайте вывод о компромиссе «скорость vs память».

**Задача 12. Скользящее среднее.**
Дан `a` длины `10^5`. Посчитайте скользящее среднее окном `k = 10`:
- цикл: для каждого `i` от `k-1` до `n-1` суммировать `k` предыдущих;
- NumPy: `np.convolve(a, np.ones(k)/k, mode='valid')`.

Сравните. Обратите внимание: наивный цикл — \(O(n \cdot k)\), NumPy через свёртку — \(O(n \cdot k)\), но константа в 100× меньше (C-цикл). Объясните, почему алгоритмически это не ускорение, а «константный фактор», и почему на практике этого достаточно.

**Задача 13. Кумулятивная сумма (running sum).**
Дан `a` длины `10^5`. Посчитайте `cumsum[i] = a[0] + ... + a[i]`:
- цикл: `s = 0; for x in a: s += x; result.append(s)`;
- NumPy: `np.cumsum(a)`.

Сравните. Проверьте совпадение до `1e-9`. Обсудите: почему `np.cumsum` точнее наивного цикла на больших `n` (подсказка: NumPy использует более устойчивый алгоритм суммирования, но **не** `fsum` — для максимальной точности нужно `np.cumsum` с `dtype=np.float64` и проверка).

**Задача 14. Группировка по значению.**
Дан `ints` — массив целых `0..99` длины `10^6`. Посчитайте частоту каждого значения:
- цикл: словарь `{v: count}`;
- NumPy: `np.bincount(ints, minlength=100)`.

Сравните. Обратите внимание: `bincount` требует неотрицательных целых — это ограничение, но в обмен даёт скорость. Проверьте совпадение частот. Объясните: в каких случаях словарь лучше (произвольные значения, строки), а в каких — `bincount` (целые в узком диапазоне).

**Задача 15. Полный кейс: обработка «сырых» измерений.**
Дан `raw` формы `(10^5, 3)` — 100 000 измерений по 3 датчика (сгенерируйте через `rng.normal(size=(100_000, 3))` и добавьте 100 выбросов `raw[rng.integers(0, 100_000, 100), rng.integers(0, 3, 100)] = 1e6`).

Выполните пайплайн:
1. Отфильтровать выбросы: `np.abs(raw - raw.mean(axis=0)) > 5 * raw.std(axis=0)`.
2. Заменить выбросы на `np.nan`, затем на среднее по столбцу (`np.nanmean` + `np.where`).
3. Нормировать каждый столбец: `(raw - raw.mean(axis=0)) / raw.std(axis=0)`.
4. Посчитать среднее и std по каждому датчику **после** нормировки (должно быть ≈ 0 и ≈ 1).
5. Посчитать корреляционную матрицу `np.corrcoef(raw.T)` — форма `(3, 3)`.

Сравните полный пайплайн:
- **циклы**: всё через `for`, списки, ручные индексы;
- **NumPy**: всё через маски, broadcasting, агрегации.

Выведите таблицу «шаг → время цикла → время NumPy → ускорение → SLOC». В конце — вывод: на каком шаге ускорение максимально и почему; сколько строк экономит NumPy; какие места цикла были самыми «нечитаемыми».
